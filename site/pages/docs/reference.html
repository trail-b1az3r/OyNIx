The default profile is called default. Back up ~/.config/oynix and ~/.local/share/oynix to keep everything.

Hyprland and tiling window managers

With Open settings in › A separate window, the settings window is a dialog of the browser window, so Hyprland floats it. Its title is always OyNIx Settings, so you can write rules for it:

# ~/.config/hypr/hyprland.conf: tile it instead
windowrulev2 = tile, title:^(OyNIx Settings)$

# or keep it floating at a fixed size
windowrulev2 = float, title:^(OyNIx Settings)$
windowrulev2 = size 980 700, title:^(OyNIx Settings)$

Sway and i3 users can match the same title with for_window [title="^OyNIx Settings$"].

WebUSB

Sites served over HTTPS can ask to use a USB device, which is how web-based board flashers, hardware-wallet apps and microcontroller IDEs work. A site has to ask from a click, you choose the device in a picker, and the permission is kept for that site until you remove it in Settings › Websites › USB Devices. Keyboards, mice, storage, audio and video devices can’t be claimed this way.

Linux only lets your user open some USB devices. If a site says access was denied, add a udev rule for the device. Find its IDs with lsusb (for example 2341:8036):

echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="2341", ATTR{idProduct}=="8036", TAG+="uaccess"' | \
  sudo tee /etc/udev/rules.d/70-oynix-webusb.rules
sudo udevadm control --reload && sudo udevadm trigger

Graphics

On Wayland, OyNIx draws its interface with OpenGL ES. On X11 it uses Vulkan 1.3 or 1.2 when the driver supports it, and OpenGL otherwise. Settings › About shows what it’s using, and --gpu vulkan|gles|opengl overrides the choice.

Vulkan isn’t the Wayland default because of how it waits for the screen: compositors such as Hyprland stop telling hidden windows when to draw, and a Vulkan window then waits indefinitely, which froze the whole browser until it was shown again. OpenGL ES on Wayland waits with a time limit instead.

If OyNIx freezes

OyNIx notices when its interface stops responding for more than a second and a half and notes it in Settings › About › Responsiveness (also ~/.cache/oynix/PROFILE/freezes.log), with the graphics backend and whether the window was in the background. Please include those lines when you report a freeze.

Building from source

You need Rust (stable) and Qt 6.10 or newer with Qt WebEngine. Most distributions don’t ship that yet, so a script fetches Qt 6.12 into the source folder:

git clone {{repo}}.git && cd OyNIx
./scripts/deps-ubuntu.sh     # libraries, rustup and Qt 6.12 in ./.qt
cargo build --release
./scripts/install.sh         # ~/.local/bin/oynix and a desktop entry

To use a Qt you already have, point QMAKE at it: QMAKE=/usr/bin/qmake6 cargo build --release. scripts/build-deb.sh and scripts/build-pkg.sh make the release packages.
