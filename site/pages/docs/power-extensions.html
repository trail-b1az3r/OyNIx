What a power extension is

A .poweroynix is an ordinary OyNIx extension — oynix.json, code.ts, content.css and the optional files — with "power": true in oynix.json and a signature, oynix.sig. In exchange for being checked, it gets abilities ordinary extensions don’t:

File or settingWhat it does
network.tsRuns in the background with oynix.network: add blocker rules, add request headers, watch requests, fetch without cross-origin limits.
theme-shape.qmlDraws every expressive shape in the browser — start page tiles, badges, dialogs — while the extension’s browser style is chosen.
extra.mdA page written in Markdown. OyNIx renders it (tables, task lists, footnotes) in light and dark.
images/Pictures (PNG, JPEG, GIF, WebP, SVG, AVIF; 2 MB in all) for pages, panels and code: oynix.image("logo.png") gives a data: URL.
filters.txt with "permissions": ["filters"]Adblock/uBlock rules added to OyNIx’s blocker while the extension is on.
manifest.json (Manifest V2 or V3)A Chrome or Firefox extension half that runs alongside, and gets the powerful APIs — native messaging, webRequest, cookies, browsingData, management — without anyone turning on Developer mode. Its manifest still has to ask for each permission.

Wallbreaker, which gets you past “please turn off your ad blocker” walls, is a power extension that ships with OyNIx.

Verification

OyNIx installs a .poweroynix only when oynix.sig is a valid Ed25519 signature over the SHA3-256 hash of every other file in the package, made by a key in packaging/poweroynix/trusted-keys.txt, which is compiled into OyNIx. A package changed after signing, signed by an unknown key, or not signed at all is refused with a message saying which. The Extension Gallery refuses to list one under the same rule.

Signing is the review: the people who hold trusted keys read the whole extension before they sign it. Extensions that ship inside OyNIx are the one exception — they came with the browser.

network.ts

network.ts runs in a hidden page of its own as long as the extension is on. Everything it asks for goes through OyNIx, checked against a secret only that page knows, so no website or other extension can speak for it. Requests from private windows never reach it, and its headers are never added there.

// Block a tracker the lists missed (Adblock syntax; replaces this extension's earlier list)
oynix.network.block(["||metrics.example.com^", "/beacon.js$script"]);

// Send an API key to one service
oynix.network.setRequestHeader("https://api.example.com/*", "X-Api-Key", "…");

// See requests as they happen
oynix.network.onRequest(r => {
  if (r.blocked) console.log("blocked", r.url, "on", r.firstParty);
});

// Fetch without cross-origin limits
const res = await oynix.network.fetch("https://status.example.com/api.json");
const status = await res.json();
Call
block(rules)An array or newline-separated string of blocker rules. Replaces what this extension set before; an empty list removes them.
setRequestHeader(pattern, name, value)For addresses matching pattern (* wildcards over the whole URL). Headers the browser manages (Cookie, Host, Origin, Referer…) can’t be set.
clearRequestHeaders()Removes this extension’s header rules.
onRequest(fn)fn({url, firstParty, method, type, blocked, time}) for each request, delivered in small batches.
fetch(url, {method, headers, body})Resolves to {status, ok, headers, text(), json()}. Up to 16 MB.

network.ts also has oynix.data (your extra.jsonl) and oynix.image(name). When the extension is turned off, its rules and headers go away at once.

theme-shape.qml

A QML item that draws one shape, checked by the same rules as panels (Qt Quick imports only; no parent, window, loaders or network). It needs shape and color properties and may have size, borderColor, borderWidth and rotationOffset; OyNIx keeps them up to date. shape is the name the browser asked for ("cookie9", "flower", "circle"…), so you can draw some differently from others.

import QtQuick
Item {
    id: s
    property string shape: "circle"
    property color color: "transparent"
    Rectangle {
        anchors.fill: s
        radius: s.shape === "circle" ? s.width / 2 : s.width * 0.22
        color: s.color
    }
}

It applies while the extension is chosen in Settings › Appearance › Browser Style, alone or together with a theme.json.

extra.md and images/

If there’s no extra.html, an extra.md becomes the extension’s page, opened from its toolbar button. Pictures in images/ can be used from it with ordinary relative links: ![logo](images/logo.png).

Making one

  1. Build it as an ordinary OyNIx extension first, without "power": true. The Chrome or Firefox half can be tested with Settings › Extensions › Developer mode › Allow powerful extension APIs.
  2. Add "power": true and the power files.
  3. Ask a key holder to review and sign it (or, if you maintain OyNIx, sign it yourself): 
    python3 scripts/poweroynix.py sign my-extension --key you.poweroynix-key --pack My-Extension-1.0.0.poweroynix
python3 scripts/poweroynix.py verify My-Extension-1.0.0.poweroynix
  4. Install the .poweroynix (open it in OyNIx, or oynix --install-extension), or submit the signed folder to the Gallery.

Any change to any file after signing — including the signer’s own — needs a new signature. scripts/poweroynix.py keygen "Your Name" makes a key pair; the public line goes in trusted-keys.txt and takes effect in the next OyNIx release.
