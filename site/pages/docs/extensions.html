From the Extension Gallery

Open the Extension Gallery in OyNIx and click Add to OyNIx. The browser asks before installing. In other browsers the button downloads the package instead; install it with oynix --install-extension, or open the downloaded file in OyNIx.

From addons.mozilla.org

Open any add-on on addons.mozilla.org. Mozilla shows its own install button only to Firefox, so OyNIx adds an Add to OyNIx button in the bottom corner of the page. It fetches the add-on’s current version and asks before installing.

Firefox extensions are adapted on install: Firefox-only manifest keys are removed, background scripts become a service worker on Manifest V3, and browser.* calls return promises as Firefox’s do.

From a file or folder

Settings › Extensions › From File… takes .crx, .xpi, .zip and .oynix files; From Folder… loads an unpacked extension, which is handy while you write one. Opening any .xpi, .crx or .oynix link in OyNIx also offers to install it. From a terminal:

oynix --install-extension ublock_origin.xpi --install-extension ./my-extension
oynix --list-extensions

Manifest V2 and V3 both work. Each extension can be turned off or removed in Settings › Extensions; if one fails to load, the reason is shown there.

What works

OyNIx runs extensions on Chromium’s engine through Qt WebEngine, and provides most of the chrome.* and browser.* APIs itself:

What doesn’t

webRequest blocking, declarativeNetRequest, devtools panels, native messaging, commands shortcuts and Firefox sidebars aren’t available. Calls to them fail rather than crash the extension. This mostly affects network ad blockers like uBlock Origin: their element hiding and popup work, but their request blocking doesn’t, and OyNIx’s built-in blocker does that job instead.
