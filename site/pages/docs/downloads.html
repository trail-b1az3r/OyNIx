Choose a release

The Downloads page reads published release metadata from the official OyNIx GitHub repository. Stable releases are shown one version at a time, with the release date and every attached asset. Pre-releases are kept in their own tab so they are not confused with the recommended stable builds.

Choose the package that matches your distribution:

PackageTypical systemInstall
.debDebian, Ubuntu, Linux Mint and derivativessudo apt install ./oynix_VERSION_amd64.deb
.pkg.tar.zstArch Linux and derivativessudo pacman -U oynix-VERSION-1-x86_64.pkg.tar.zst
.flatpakSystems with Flatpak supportflatpak install --user ./OyNIx-VERSION.flatpak

Not every release necessarily contains every package format. Only use a package that is actually listed under that version. The Downloads page links to each asset’s direct download URL; it does not send you through a release-details page.

Verify a download

When a release includes SHA256SUMS, download it into the same directory as the package. Then run:

sha256sum -c SHA256SUMS --ignore-missing

A result ending in OK means the local file matches the published checksum. A failure means the file is incomplete, damaged or not the file described by that checksum. Download it again before installing.

Legacy archive

Versions v4.3 and older are grouped in the collapsed Legacy archive. Open the archive, find the exact version you need, and choose one of its attached files. The legacy list uses the same direct asset links as current releases.

{{shape:cookie9:warning}}

Legacy builds may lack security fixes, compatibility fixes and current features. Use them only when you specifically need an older build for compatibility or recovery. For normal use, choose a current stable version.

Pre-releases

Pre-releases are development builds published before a stable release. They may contain unfinished features or regressions. Keep them separate from your normal installation unless you are testing a fix or helping verify a change.

Automatic updates

OyNIx checks for updates once a day by default. When an update is available, it can download the package in the background and verify its SHA-256 checksum before offering installation. The package manager performs the installation and asks for authorization; restarting OyNIx restores your tabs.

  • APT and pacman installs: OyNIx can offer to install the downloaded package through the system package manager.
  • AUR installs: OyNIx can notify you about a new release, but updates remain the responsibility of your AUR helper. Run yay -Syu.
  • Source builds: OyNIx can tell you that a newer release exists, but it does not replace your locally built program.

Open Settings › About › Updates to check immediately, choose the beta channel, or disable update checks and background downloads.

Downloads page troubleshooting

  • “Releases could not be loaded”: check your connection and try again. The release list is supplied by GitHub’s public Releases API, which can be temporarily unavailable or rate-limited.
  • A version has no files: that release has no downloadable assets attached. Choose another release or build from source.
  • A package is missing: not every release publishes every package format. Do not rename a package for another distribution.
  • The download fails: retry the asset link and verify the checksum before installing.
