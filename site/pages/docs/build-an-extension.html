The three files

An extension is a folder (or a zip of one, named .zip or .oynix) containing exactly these files. All three must exist, even if one is empty.

FileContains
oynix.jsonName, version and where the extension runs
content.jsJavaScript run on matching pages
content.cssStyles added to matching pages

The quickest start is Settings › Extensions › New Extension, which writes a working template into your extensions folder and installs it. Edit the files, then turn the extension off and on again to reload it.

oynix.json

{
  "name": "Reading Time",
  "version": "1.0.0",
  "description": "Shows how long an article takes to read.",
  "matches": ["*://*/*"],
  "exclude": ["*://mail.example.com/*"],
  "run_at": "document_idle",
  "world": "isolated"
}
KeyMeaning
nameRequired. Shown in Settings and the install prompt.
versionAny dotted version. Installing a newer one replaces the old.
descriptionOne sentence.
matchesPages to run on, as match patterns. "*://*/*" means every site.
excludePages to skip, in the same form.
run_atdocument_start (before the page’s own scripts), document_end (default; the page is parsed) or document_idle (after it has loaded).
worldisolated (default): your script sees the page’s DOM but not its JavaScript variables, and the page can’t see yours. main: runs alongside the page’s scripts, for when you must call or replace the page’s own functions.

content.js and content.css

The stylesheet is added first, then the script runs inside its own function, so top-level vars don’t leak. Write plain JavaScript; there’s no build step and no special API. In the isolated world you can use everything a page can, including fetch (subject to the site’s CORS rules) and navigator.clipboard during a key press.

Keep it small and predictable. Prefer reacting to events over polling, don’t scan the whole document on every mutation, and stay out of the way when the user is typing in a field.

Packaging

Zip the three files with no enclosing folder and give the file a .oynix extension:

cd my-extension && zip ../my-extension-1.0.0.oynix oynix.json content.js content.css

Publishing to the Gallery

The Gallery is built from the gallery/ folder of the OyNIx repository. To add yours, open a pull request with a folder containing your three files. Add a gallery section to oynix.json for the listing:

"gallery": {
  "category": "Reading",
  "author": "Your name",
  "shape": "softBurst",
  "summary": "A quiet clock for long articles.",
  "about": "A paragraph or two: what it does, where it runs, and what it leaves alone."
}

Gallery extensions are reviewed by reading them, so they must be readable: no minified or obfuscated code, no remote scripts, no network requests that send page content anywhere, and no analytics. The listing page shows your code in full.

shape picks the badge from the browser’s own set: circle, cookie4, cookie6, cookie7, cookie9, cookie12, flower, clover4, clover8, sunny, burst, softBurst, pentagon or pill.
