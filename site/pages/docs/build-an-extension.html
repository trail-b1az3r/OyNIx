The files

An extension is a folder, or a zip of one named .oynix (or .zip):

FileContains
oynix.jsonRequiredName, version and where the extension runs
code.tsRequiredTypeScript run on matching pages
content.cssRequiredStyles added to matching pages (may be empty)
graphics.qtOptionalA panel in the browser’s toolbar, written in QML
extra.htmlOptionalA page in the toolbar instead, for when you’d rather write HTML
extra.jsonlOptionalData your code can read: one JSON value per line, up to 4 MB
icon.png / icon.svgOptionalThe toolbar and Settings icon

The quickest start is Settings › Extensions › New Extension, which writes a working template into your extensions folder and installs it. Edit the files, then turn the extension off and on again; OyNIx recompiles code.ts when it changes.

oynix.json

{
  "name": "Reading Time",
  "version": "1.0.0",
  "description": "Shows how long an article takes to read.",
  "matches": ["*://*/*"],
  "exclude": ["*://mail.example.com/*"],
  "run_at": "document_idle",
  "world": "isolated"
}
KeyMeaning
nameRequired. Shown in Settings, the toolbar and the install prompt.
versionAny dotted version. Installing a newer one replaces the old.
descriptionOne sentence.
matchesPages to run on, as match patterns. "*://*/*" means every site.
excludePages to skip, in the same form.
run_atdocument_start (before the page’s own scripts), document_end (default; the page is parsed) or document_idle (after it has loaded).
worldisolated (default): your code sees the page’s DOM but not its JavaScript variables, and the page can’t see yours. main: runs alongside the page’s scripts. Messaging with a panel only works in isolated.

code.ts

Write TypeScript. OyNIx compiles it when the extension is installed, and again whenever the file changes, by removing the types and turning TypeScript-only syntax such as enum into JavaScript. It doesn’t type-check, so code with type errors still runs; use tsc --noEmit or your editor to check types. A syntax error stops the install and names the line.

The stylesheet is added first, then your code runs in its own scope. Besides everything a page can use, it gets an oynix object. Paste this declaration at the top of code.ts for editor completion (it disappears when compiled):

declare const oynix: {
  readonly id: string;
  /** Records from extra.jsonl, one per line. */
  readonly data: readonly unknown[];
  /** Send a message to graphics.qt or extra.html. */
  post(message: unknown): Promise<void>;
  onMessage(listener: (message: unknown) => void): void;
  /** Open this extension's panel. */
  openPanel(): Promise<void>;
};

graphics.qt: a panel

A graphics.qt file is a QML document. OyNIx adds a button for the extension to the toolbar, and clicking it shows the panel in a popover drawn the same way as the rest of the browser. It talks to code.ts through an extension object, passing JSON text:

import QtQuick
import QtQuick.Controls.Basic

Rectangle {
    id: root
    implicitWidth: 300; implicitHeight: 160
    color: "#dde1ff"
    Column {
        anchors.centerIn: root
        spacing: 10
        Text { id: out; text: "Words in extra.jsonl: " + JSON.parse(extension.data).length }
        Button { text: "Count this page"; onClicked: extension.post(JSON.stringify({ cmd: "count" })) }
    }
    Connections {
        target: extension
        function onMessage(json) { out.text = JSON.parse(json).words + " words" }
    }
}

And on the page side, in code.ts:

oynix.onMessage((m: any) => {
  if (m.cmd === 'count') oynix.post({ words: document.body.innerText.split(/\s+/).length });
});

extension has id, data (the extra.jsonl records as JSON text), post(json), the message(json) signal and close().

What a panel can’t do

A panel runs in its own QML engine, cut off from the rest of OyNIx. OyNIx checks the file before running it, on install and again each time it opens, and refuses panels that break these rules:

  • Imports only from QtQuick, QtQuick.Layouts, QtQuick.Controls, QtQuick.Controls.Basic, QtQuick.Shapes, QtQuick.Effects, QtQml and QtQml.Models.
  • No network: requests fail, and XMLHttpRequest isn’t available.
  • No QML made at run time: no Loader, Qt.createQmlObject or Qt.createComponent.
  • parent and Window aren’t available, because they lead out of the panel into the browser. Give items an id and refer to that instead; OyNIx sizes the root item to the popover.
  • this, eval, Function and constructor aren’t available.
  • From Qt, only colours, geometry, fonts, enums such as Qt.AlignLeft, Qt.binding, Qt.callLater and the formatting functions.

The error names the line and the word that broke a rule.

extra.html: a page

If you’d rather write HTML, include extra.html instead of graphics.qt. It opens in the same toolbar popover and gets the same oynix object as code.ts, with post going to code.ts and onMessage receiving from it. It can’t load anything from the network or from your files, so keep it to one file with its styles and scripts inline. Links in it open in a new tab.

extra.jsonl: data

Put word lists, rules or settings in extra.jsonl, one JSON value per line. Blank lines are skipped. The file is checked on install, and a malformed line stops the install with its line number. Your code sees the records as oynix.data, and a panel as extension.data. Because the data is sent to every page the extension runs on, keep it under 4 MB.

Packaging

Zip the files with no enclosing folder and give the file a .oynix extension:

cd my-extension && zip ../my-extension-1.0.0.oynix oynix.json code.ts content.css graphics.qt

Publishing to the Gallery

The Gallery is built from the gallery/ folder of the OyNIx repository. To add yours, open a pull request with a folder containing your files. Add a gallery section to oynix.json for the listing:

"gallery": {
  "category": "Reading",
  "author": "Your name",
  "shape": "softBurst",
  "summary": "A quiet clock for long articles.",
  "about": "A paragraph or two: what it does, where it runs, and what it leaves alone."
}

Gallery extensions are reviewed by reading them, so they must be readable: no minified or obfuscated code, no remote scripts, no network requests that send page content anywhere, and no analytics. The listing page shows every file in full. Check yours with tsc --noEmit --strict before sending it.

shape picks the badge from the browser’s own set: circle, cookie4, cookie6, cookie7, cookie9, cookie12, flower, clover4, clover8, sunny, burst, softBurst, pentagon or pill.
